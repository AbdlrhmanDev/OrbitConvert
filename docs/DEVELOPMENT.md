# Development

## Prerequisites

- Windows 10/11 x64
- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) (`global.json` pins the 10.0 feature band)
- Optional, for integration tests and full functionality: FFmpeg, Pandoc, LibreOffice, 7-Zip
- An editor with .NET 10 support: a current Visual Studio, Rider, or VS Code with C# Dev Kit

## Common commands

```powershell
dotnet build OrbitConvert.sln                         # Debug build
dotnet test OrbitConvert.sln                          # all tests
dotnet test tests/OrbitConvert.Core.Tests             # fast, no external tools
dotnet run --project src/OrbitConvert.App             # desktop app
dotnet run --project src/OrbitConvert.Cli -- --help   # command line
pwsh scripts/build-release.ps1                        # release artifacts in artifacts\release
```

## Tests

| Project | Needs | What it covers |
|---|---|---|
| `OrbitConvert.Core.Tests` | nothing | Signature detection, capability registry, output naming and collisions, engine failure/cancel/validation paths, queue concurrency/pause/cancel/retry, page ranges |
| `OrbitConvert.Converters.Tests` | nothing (bundled engines only) | FFmpeg argument building, archive extraction security, real ImageMagick and PDF conversions, process runner (exit codes, argument quoting, process-tree kill, timeouts), tool discovery, checksum enforcement for downloads |
| `OrbitConvert.Integration.Tests` | FFmpeg, Pandoc, LibreOffice, 7-Zip (each optional) | End-to-end conversions through the production service graph, verified with ffprobe and by reading the outputs; cancellation leaves no FFmpeg process behind |

Integration tests use `[SkippableFact]`: a missing tool is reported as *skipped*. To run them, put the
tools on `PATH` or set `ORBITCONVERT_TOOLS_DIR` to a folder that contains them (searched up to four
levels deep), for example:

```powershell
$env:ORBITCONVERT_TOOLS_DIR = "D:\devtools"   # contains ffmpeg\...\bin\ffmpeg.exe, pandoc\..., 7zip\7zr.exe
dotnet test tests/OrbitConvert.Integration.Tests
```

Media fixtures are generated at test time with FFmpeg's `lavfi` sources; documents are generated with
Pandoc; PDFs and images with PDFsharp and Magick.NET. The repository contains no binary test fixtures.

## Running the app against test data

Set `ORBITCONVERT_DATA` to a scratch folder so experiments do not touch your real settings or history:

```powershell
$env:ORBITCONVERT_DATA = "$env:TEMP\oc-dev"
dotnet run --project src/OrbitConvert.App -- --radial C:\path\to\file.png
```

Command-line switches are documented in `src/OrbitConvert.App/StartupArguments.cs`.

## Release builds

`scripts/build-release.ps1` runs the tests, publishes the app and CLI **self-contained** for `win-x64`,
creates the portable ZIP (with `portable.txt`), builds the MSI with WiX 5 (`installer/`), and writes
`SHA256SUMS.txt`. The installer project builds with plain `dotnet build`; no WiX installation is needed.

If you change `LICENSE`, regenerate the installer's license page: `python scripts/make-license-rtf.py`.

The logo and `orbitconvert.ico` are generated by `scripts/IconGen` (WPF rendering + Magick.NET):
`dotnet run --project scripts/IconGen`.

## Conventions

- Nullable reference types are enabled and nullable warnings are errors.
- User-facing failures throw `ConversionException` with a message a non-technical user can act on;
  put tool output in `technicalDetail`.
- Never build command lines by concatenation: use `ProcessSpec` argument lists.
- Converters must write only inside `ConversionContext.WorkDirectory`.
- Do not add a target that you cannot produce correctly; mark partial capabilities `Experimental` and
  describe the `Limitations`.

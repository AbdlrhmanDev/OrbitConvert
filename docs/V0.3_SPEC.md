# OrbitConvert 0.3 Product Completion Specification

**Author:** Codex with AbdlrhmanDev  
**Date:** 2026-10-19  
**Status:** Approved — the owner explicitly requested implementation of every improvement listed in the product review  
**Reviewer:** AbdlrhmanDev

## Context

OrbitConvert 0.2 is a stable, tested local converter, but several experiences are incomplete: some tools are labelled Planned, two external engines cannot be installed from the app, the UI is English-only, and advanced document/media workflows require manual work. Version 0.3 completes the visible product surface and makes missing dependencies understandable and recoverable.

The release must preserve the product's defining privacy property: user files stay on the device. Network access is limited to explicit, checksum-verified dependency downloads and update checks. Existing presets, history, automation, shell activation and command-line behavior must remain compatible.

## Functional Requirements

- FR-1: Complete tool surface.
Every visible image/PDF tool MUST either execute a real operation or be removed from the UI. Image Edit, Annotate and Redact, plus PDF Reorder, MUST be implemented.

- FR-2: Dependency setup.
Settings MUST offer explicit, checksum-verified installation flows for FFmpeg, Pandoc, 7-Zip, LibreOffice and Ghostscript, show progress, support cancellation, and explain disk size and license before download.

- FR-3: Localization.
All user-visible application strings MUST come from localization resources. English and Arabic MUST ship in 0.3. Arabic MUST switch the main UI to RTL while file paths, media times and technical values remain readable LTR.

- FR-4: Conversion feedback.
Conversion screens MUST show input preview when safe, progress, elapsed time, an estimated remaining time when measurable, output-size estimate when measurable, and actions to open the output or its folder.

- FR-5: PDF workflows.
Users MUST be able to reorder pages with thumbnails, remove pages, rotate selected pages and save atomically. Optional OCR MUST convert scanned PDF pages into a searchable PDF without uploading data.

- FR-6: Image workflows.
Users MUST be able to adjust brightness/contrast, flip, annotate with text/arrows/shapes, and permanently redact rectangular regions. The editor MUST provide a before/after preview and MUST flatten annotations/redactions into output pixels.

- FR-7: Metadata.
Users MUST be able to view common EXIF fields, identify GPS fields and remove selected metadata fields or all metadata.

- FR-8: Media workflows.
Users MUST be able to trim audio/video by start and end time. MKV inputs MUST expose subtitle streams and allow copying, dropping or selecting a stream where supported by FFmpeg.

- FR-9: Batch flexibility.
Mixed batches MUST support a target per input file while retaining the existing shared-target fast path. Jobs MUST remain cancellable and bounded by the configured parallelism.

- FR-10: Image formats.
HEIC output MUST be exposed only when an installed encoder proves write capability. It MUST otherwise remain disabled with a precise explanation.

- FR-11: Windows integration.
The legacy Explorer verb MUST remain supported. A signed MSIX/sparse-package path and modern Windows 11 `IExplorerCommand` handler MUST be buildable when signing identity values are supplied. Unsigned developer builds MUST continue to work without it.

- FR-12: Architectures.
Release scripts MUST support win-x64 and win-arm64. Architecture-specific artifacts MUST be named unambiguously.

- FR-13: Reliability.
The application MUST handle missing tools, offline operation, malformed files, large files and cancellation without crashing or replacing original input files.

- FR-14: Product polish.
Error messages MUST lead with a plain-language cause and recovery action, with technical detail available separately. No visible control may display raw object representations.

## Non-Functional Requirements

- **NFR-1 — Privacy:** File contents MUST NOT be uploaded. Dependency and update requests MUST NOT include file names or conversion history.
- **NFR-2 — Security:** All managed downloads MUST use HTTPS, pinned versions and SHA-256 verification before extraction or execution. Archive extraction MUST reject traversal and link escapes.
- **NFR-3 — Performance:** Opening the main window SHOULD reach an interactive state within 2 seconds on the existing QA machine. UI work MUST not synchronously decode full-resolution images or PDF pages. Preview memory SHOULD remain under 256 MB per open editor.
- **NFR-4 — Accessibility:** Interactive controls MUST have accessible names, keyboard focus, visible focus cues and a non-color-only state indicator. Reduced-motion mode MUST suppress nonessential animation.
- **NFR-5 — Compatibility:** Windows 10 22H2 and current Windows 11 MUST be supported. Mixed-DPI movement MUST not distort or strand windows off-screen.
- **NFR-6 — Quality:** All existing tests plus new requirement tests MUST pass. A release build MUST complete with zero warnings from project code.
- **NFR-7 — Atomicity:** All destructive-looking operations MUST write to a temporary output and replace/move only after validation succeeds.

## Acceptance Criteria

### AC-1: Visible tools are functional (FR-1)
Given any tool card visible to the user, when it is activated, then it opens a working editor/action or clearly reports a missing optional engine, and no card says Planned.

### AC-2: Verified dependency installation (FR-2, NFR-2)
Given a missing supported dependency, when Install is confirmed, then progress is shown and the tool becomes available only after its pinned SHA-256 matches; a mismatch deletes the download.

### AC-3: Arabic direction and localization (FR-3)
Given Arabic is selected, when the app is restarted or resources refresh, then navigation and content are Arabic/RTL and paths remain LTR. Switching back restores English/LTR.

### AC-4: Conversion feedback (FR-4)
Given an active measurable conversion, when progress changes, then elapsed/remaining values update without blocking the UI; completion exposes Open and Show in folder.

### AC-5: Atomic PDF page editing (FR-5, NFR-7)
Given a multipage PDF, when pages are reordered, removed or rotated and saved, then page count/order/rotations match the editor and the source remains unchanged.

### AC-6: Local OCR (FR-5)
Given a scanned PDF and an available OCR engine, when OCR runs, then the output contains selectable text; without the engine the UI explains how to install it.

### AC-7: Flattened image edits (FR-6)
Given an image edit containing adjustments, annotation and redaction, when exported, then output pixels reflect the preview and redacted pixels cannot be recovered by removing metadata or layers.

### AC-8: Selective metadata removal (FR-7)
Given an image with EXIF/GPS, when selected fields are removed, then retained fields remain and removed fields cannot be read from the output.

### AC-9: Media trimming (FR-8)
Given media with a valid trim range, when converted, then output duration is within one frame/sample tolerance of the range. Invalid ranges are rejected before FFmpeg starts.

### AC-10: Subtitle stream handling (FR-8)
Given MKV subtitle streams, when Copy, Drop or Select is chosen, then generated FFmpeg arguments and probed output match the choice.

### AC-11: Per-file batch targets (FR-9)
Given heterogeneous files with per-file targets, when the batch starts, then each job uses its assigned target and one failure does not cancel unrelated jobs.

### AC-12: HEIC capability gate (FR-10)
Given no HEIC writer, when targets are loaded, then HEIC output is disabled. Given a detected writer and a passing sample encode, HEIC is enabled and output signature validates.

### AC-13: Optional modern Explorer package (FR-11)
Given unsigned development configuration, when a normal MSI or portable build runs, then it succeeds without sparse packaging. Given signing identity values, the sparse project emits its package and modern Explorer command registration.

### AC-14: Architecture-specific releases (FR-12)
Given x64 or arm64 release selection, when the release script runs, then publish output and artifact names match that architecture and the managed test suite passes.

### AC-15: Recoverable failures (FR-13, FR-14)
Given offline mode, missing tools, corrupt input or cancellation, when an operation fails, then the app remains responsive, preserves input, cleans temporary output and shows an actionable message.

## Edge Cases

- EC-1: Dependency host offline, partial download, checksum mismatch, insufficient disk space and locked install directory.
- EC-2: RTL text mixed with Windows paths, file extensions, percentages and timestamps.
- EC-3: Zero-page/corrupt/encrypted PDF; removing all pages; duplicate page references; page count too large for eager thumbnails.
- EC-4: Huge or animated images; unsupported color profiles; transparent redaction output; text glyph unavailable.
- EC-5: Media with unknown duration, variable frame rate, no audio, no subtitles, multiple subtitle languages or negative timestamps.
- EC-6: Batch target becomes unavailable after planning; output collision; cancellation during external process shutdown.
- EC-7: HEIC codec reports support but fails a sample encode.
- EC-8: Explorer package identity missing, invalid or unsigned.
- EC-9: Mixed-DPI monitor removed while an editor or Orbit Menu is open.

## API Contracts

```typescript
interface DependencyPackage {
  tool: string;
  version: string;
  downloadUrl: string;
  sha256: string;
  license: string;
  unpackedBytes?: number;
}

interface PageEdit { sourceIndex: number; rotationDegrees: 0 | 90 | 180 | 270; include: boolean; }
interface PdfEditPlan { inputPath: string; pages: PageEdit[]; outputPath: string; ocrLanguage?: string; }

interface ImageEditPlan {
  inputPath: string;
  brightness: number;
  contrast: number;
  flip: "none" | "horizontal" | "vertical";
  annotations: Annotation[];
  redactions: Rectangle[];
}

interface MediaEditPlan {
  inputPath: string;
  start?: string;
  end?: string;
  subtitleMode: "copy-all" | "drop-all" | "select";
  subtitleStreamIndex?: number;
}

interface BatchPlanItem { inputPath: string; targetKey: string; options: object; }
```

N/A — OrbitConvert is a local desktop application and exposes no HTTP endpoints. The interfaces below are its in-process service contracts. Errors use the existing `ConversionException` contract: a plain-language message, optional recovery guidance, and optional technical detail.

## Data Models

| Model | Field | Type | Constraint |
|---|---|---|---|
| AppSettings | Language | string | `en` or `ar` in 0.3 |
| AppSettings | PreviewEnabled | bool | defaults true |
| PdfEditPlan | Pages | ordered list | at least one included page |
| Annotation | Kind | enum | text, arrow, rectangle, ellipse |
| Annotation | Bounds/Color/Stroke | value types | finite, inside image canvas |
| Rectangle | X/Y/Width/Height | double | normalized 0..1, positive size |
| MediaEditPlan | Start/End | duration | start >= 0; end > start |
| BatchPlanItem | TargetKey | string | must resolve at execution time |
| MetadataSelection | Keys | string set | only keys present in source |

## Implementation Sequence

1. Localization infrastructure and dependency-install model.
2. Complete existing Planned image/PDF UI with tested editor services.
3. Preview/progress/output actions and metadata selection.
4. Media trim/subtitle contracts and per-file batch targets.
5. OCR/HEIC capability adapters.
6. ARM64 and optional signed sparse-package build path.
7. Windows 10/11, offline, DPI, large-file and installer validation; documentation and 0.3 release.

## Out of Scope

- OS-1: Cloud conversion, user accounts, telemetry and file-content analytics are excluded because they conflict with the local-first product.
- OS-2: A bundled proprietary HEIC encoder is excluded; capability-based support using a legally redistributable or user-installed writer satisfies FR-10.
- OS-3: Automatic purchase or provisioning of a code-signing certificate is excluded because it requires the owner's verified legal identity and payment. The build integration itself is in scope.
- OS-4: Perfect layout reconstruction for PDF-to-DOCX is impossible with the selected engines; the existing experimental label remains until OCR/layout evaluation proves otherwise.
